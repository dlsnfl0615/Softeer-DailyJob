## Mockito
### 어떤걸 테스트하는가
테스트하려는 대상이 의존하는 다른 객체들과의 상호작용을 테스트함

- **`verify(mock).method()`**: 메서드 호출 여부 검사. 호출됐는지, 몇 번 됐는지(`times(n)`), 안 됐는지(`never()`)

- **`verify(mock).method(eq("특정값"))`, `ArgumentCaptor`**: 호출 시 전달된 인자 검증. 특정 값으로 호출됐는지 확인하거나, `ArgumentCaptor`로 실제 넘어온 객체를 캡처해서 세부 검증

- **`InOrder`**: 호출 순서 검증. 여러 mock 간에 어떤 메서드가 먼저/나중에 호출됐는지 확인

- **`when(mock.method()).thenReturn(값)`**: 반환값 조작. 특정 입력에 대해 원하는 값을 리턴하도록 설정

- **`when(mock.method()).thenThrow(new RuntimeException())`**: 예외 강제 발생. 특정 상황(DB 장애, 외부 API 실패 등)을 인위적으로 재현

- **`thenReturn(a, b, c)`**: 여러 번 호출 시 다른 값 반환. 첫 호출엔 a, 두 번째엔 b, 세 번째부터는 c(마지막 값 유지)

- **`doThrow()`, `doAnswer()`**: void 메서드의 부작용 흉내. void는 리턴값이 없어서 `when(...).thenThrow()`가 안 먹히므로 `doThrow(...).when(mock).method()` 형태로 사용. `doAnswer()`는 호출될 때 커스텀 로직(인자 확인, 콜백 실행 등)을 직접 정의할 때 사용

## jakarta.validation
DTO에 어노테이션 붙여서 값 받는 단계에서 조건 걸 수 있음

| 어노테이션 | 설명 |
|---|---|
| `@NotNull` | null 불가 (빈 문자열 `""`은 통과) |
| `@NotBlank` | null, 빈 문자열, 공백만 있는 문자열 모두 불가 (String 전용) |
| `@NotEmpty` | null, 빈 컬렉션/문자열 불가 (공백은 통과) |
| `@Size(min=, max=)` | 문자열 길이, 컬렉션 크기 범위 |
| `@Min` / `@Max` | 숫자 최소/최대값 |
| `@Positive` / `@Negative` | 양수/음수 |
| `@Email` | 이메일 형식 |
| `@Pattern(regexp=)` | 정규식 매칭 |
| `@Past` / `@Future` | 날짜가 과거/미래인지 |
| `@Valid` | 중첩 객체 내부까지 검증 (예: `List<Item>`의 각 Item도 검증) |

### http 요청 처리 흐름
```
클라이언트 요청
     ↓
[1] WAS(톰캣) 요청 수신
     ↓
[2] Filter 체인 (여러 개 순서대로 실행)
     ↓
[3] DispatcherServlet (Spring 진입점)
     ↓
[4] Interceptor (preHandle)
     ↓
[5] Controller (실제 비즈니스 로직)
     ↓
[6] Interceptor (postHandle)
     ↓
[7] View 렌더링 or ResponseBody 변환
     ↓
[8] Interceptor (afterCompletion)
     ↓
[9] Filter 체인 (역순으로 응답 후처리)
     ↓
클라이언트 응답
```
- filter는 spring 바깥인 서블릿 컨테이너 레벨에서 동작, interceptor는 spring 안쪽인 DispatcherServlet 내부에서 동작하므로 filter가 interceptor보다 항상 먼저 실행됨

### Filter
```java
@Component
public class LoggingFilter implements Filter {

    @Override
    public void doFilter(ServletRequest request, ServletResponse response,
                          FilterChain chain) throws IOException, ServletException {
        HttpServletRequest req = (HttpServletRequest) request;
        long start = System.currentTimeMillis();

        System.out.println("[Filter] 요청 시작: " + req.getRequestURI());

        chain.doFilter(request, response);  // 다음 필터 or 서블릿으로 전달

        long end = System.currentTimeMillis();
        System.out.println("[Filter] 요청 종료: " + (end - start) + "ms");
    }
}
```

### Interceptor
```java
// 처리
@Component
public class AuthCheckInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request,
                              HttpServletResponse response,
                              Object handler) {
        // handler를 HandlerMethod로 캐스팅하면 어떤 메서드가 호출되는지도 알 수 있음
        if (handler instanceof HandlerMethod hm) {
            System.out.println("호출될 메서드: " + hm.getMethod().getName());
        }

        String userId = (String) request.getSession().getAttribute("userId");
        if (userId == null) {
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            return false;  // false 리턴하면 컨트롤러 호출 안 됨
        }
        return true;
    }

    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response,
                            Object handler, ModelAndView modelAndView) {
        System.out.println("컨트롤러 실행 완료, 뷰 렌더링 전");
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                 Object handler, Exception ex) {
        System.out.println("응답까지 다 끝남 (예외 발생해도 여기는 실행됨)");
    }
}

---

// 등록
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new AuthCheckInterceptor())
                .addPathPatterns("/api/**")
                .excludePathPatterns("/api/login", "/api/signup");
    }
}
```
- 특정 URL 패턴별 세밀한 인증/권한 체크
- 컨트롤러 실행 전후 공통 로직 (로그인 여부, 권한 체크)
- 어떤 컨트롤러 메서드가 호출되는지 알아야 하는 로직 (@RequestMapping 어노테이션 정보 활용 등)

### 왜 Filter에서 필요한 검증 다 하지 않고 Interceptor에서도 검증함?
1. Filter는 Spring 컨텍스트 바깥이라, Filter에서 예외를 던지면 @ExceptionHandler가 못 잡음. Filter 안에서 직접 응답을 만들어줘야 함
2. Interceptor 시점(DispatcherServlet이 라우팅 끝낸 직후)에서는 이미 스프링이 아래 정보 다 파악해둔 상태니까 꺼내쓰기 편함
   - 이 URL이 어떤 @Controller/@RestController 클래스의 어떤 메서드와 매핑되는지
   - 그 메서드에 어떤 어노테이션이 붙어있는지 (@AdminOnly, @RequireAuth 같은 커스텀 어노테이션 포함)
   - 그 메서드의 파라미터 타입, @PathVariable/@RequestParam 등의 매핑 정보
3. 관심사를 분리하면 유지보수 쉬움
   - Filter는 "이 요청이 애초에 우리 애플리케이션에 들어올 자격이 있는가" (인증, 인코딩, CORS 같은 요청 자체의 유효성)
   - Interceptor는 "이 컨트롤러 로직을 실행하기 전에 Spring 관점에서 필요한 처리는?" (특정 컨트롤러 메서드의 권한, 로깅 등 비즈니스에 가까운 처리)

## 배송지 등록은 결제 하기 전인데 그럼 배송지 정보는 어디에 저장히지
1. 서버 메모리에 저장하기
   - 서버가 재시작되면 그 순간 진행 중이던 모든 사용자의 체크아웃이 동시에 사라지며 이미 클라이언트에게 서버가 저장하고 있겠다는 응답까지 준 상태라 나중에 결제 완료 단계에서 데이터 불일치 발생 가능
2. DB에 저장하기
   - 이거 하나 저장하려고 테이블 만들 순 없음
3. 클라이언트에 저장하기 ✔️
   - 입력하던 그 한 명의 사용자의 데이터만 없어짐
  
## 주소 도메인은 에러코드가 애매함
- 주소/좌표 관련해서 예외가 날 수 있는 상황은 아래와 같음
  - COMMON_011 (503, 외부 연동 서비스 장애 — 지도/PG/푸시 — "일시적인 오류가 발생했어요")
  - COMMON_012 (504, 외부 연동 서비스 응답 지연/Timeout — "응답이 지연되고 있어요")
  - COMMON_013 (400, 위치 권한 미허용 — "위치 권한을 허용해야 이용할 수 있어요")

이미 GeneralErrorCode에 EXTERNAL_SERVICE_ERROR(COMMON_011), EXTERNAL_SERVICE_TIMEOUT(COMMON_012)로 정의돼 있어서 그대로 재사용 가능함

## S3 Presigned Url
S3 버킷의 객체에 대해 AWS 계정이 없는 사람에게 임시 접근 권한을 부여하고 싶을 때, 객체를 public으로 만들지 않고도 이를 가능하게 해줌. presigned URL은 만료 시간이 지나면 더 이상 동작하지 않는 임시 접근 URL을 생성하며, 만료 시간은 생성 시 직접 정할 수 있음
