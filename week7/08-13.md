# 오늘 한 일

## 활동 내역 상세 딥링크/새로고침 시 "내역을 찾을 수 없어요" 오표시 버그

### 재현 조건

- 활동 탭에서 카드 클릭을 거치지 않고 상세 URL로 직접 진입(새로고침, 즐겨찾기 링크, 외부 공유 링크 등)
- 진입하려는 주문이 최신 20건 안에 없는 경우(오래된 주문)

### 실행 흐름

1. `ActivityDetailScreen.tsx`(부르미) / `ActivityDetailDriverScreen.tsx`(드리미) 마운트
2. 각 화면이 `useBoormiOrderById(id)` / `useDreamiOrderById(id)` 훅 호출 — `boormiOrderStore.ts` / `dreamiOrderStore.ts`에 정의
3. 훅 내부 `useEffect`가 스토어의 `orders` 배열 비어있는지 확인
4. 비어있으면(목록 화면을 거치지 않아 스토어가 초기 상태) `load()` 1회 호출 — `api.getBoormiOrders({ size: 20 })`로 커서 페이지네이션 첫 페이지(최신 20건)만 조회
5. `orders.find(o => o.id === id)`로 원하는 주문 탐색

### 문제 원인

- `useEffect`의 가드 조건(`orders.length > 0 || attemptedRef.current`)이 1번 호출 직후 곧바로 참이 됨
- 이후 이 컴포넌트 인스턴스가 살아있는 동안 `load()`/`loadMore()` 추가 호출 없음
- 찾는 주문이 최신 20건 안에 없으면 `find()`가 계속 `undefined` 반환
- 화면은 "내역을 찾을 수 없어요"를 영구 표시 — 실제로는 존재하는 주문

### 평소엔 안 보였던 이유

- 활동 목록 화면(`ActivityScreen.tsx`)이 자기 마운트 시점에 이미 같은 `load()`를 호출해 스토어를 채워둠
- 목록에서 "더보기"로 스크롤하며 원하는 주문까지 이미 캐싱해둔 상태로 카드 클릭 → 상세 진입 시 정상 동작
- 문제는 이 캐시가 전혀 없는 상태(새로고침, 딥링크)로 상세 화면에 바로 진입할 때만 노출

## 해결 방법

### 고려한 방법

#### 방법 1: `hasNext`인 동안 `loadMore()` 반복 호출해 찾을 때까지 페이지 이어받기

- 기존 목록 페이지네이션 API 재사용 가능
- 최악의 경우(오래된 주문) 수십~수백 번 요청 필요 — 응답 지연 큼
- 존재하지 않는 id·타인 주문 id는 전체 내역을 다 넘겨야 "없음" 판정 가능
- 공용 목록 스토어(`orders`)를 상세 화면이 강제로 채움 — 목록 화면 상태 오염 여지

#### 방법 2: id로 직접 조회하는 전용 API 추가

- 신규 백엔드 엔드포인트 필요(`GET /boormi/calls/{orderId}`, `GET /dreami/deliveries/{orderId}`)
- 요청 1회로 결과(있음/없음/소유자 아님) 즉시 확정
- 목록 스토어와 완전히 독립 — 상태 오염 없음

### 선택한 방법

- 방법 2(id 직접 조회) 채택
- 선택 이유: 조회 비용이 주문의 페이지 위치와 무관하게 항상 일정, 소유권 검증이 명확(`NOT_ORDER_OWNER` 403 반환 가능), 목록 화면의 전역 상태 불변

### 구현 내용

- 백엔드: `BoormiService.getMyOrder` / `DreamiService.getMyDelivery` 신규 — `orderService.getOrder(orderId)`로 조회 후 `boormiId`/`dreamiId` 일치 여부 검증
- 백엔드: `BoormiController`에 `GET /calls/{orderId}`, `DreamiController`에 `GET /deliveries/{orderId}` 추가
- 프론트: `useBoormiOrderById` / `useDreamiOrderById`를 "스토어 배열에서 검색"하는 방식에서 "id 변경 시마다 전용 API 직접 호출"하는 방식으로 재작성
- 프론트: `ActivityDetailScreen.tsx` / `ActivityDetailDriverScreen.tsx`가 훅이 직접 제공하는 `{ order, loading }`을 사용하도록 수정(스토어의 `loading` 별도 구독 제거)
